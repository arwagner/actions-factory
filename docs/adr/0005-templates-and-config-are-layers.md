# 5. Templates and the factory config are layers of one stack

A template can extend one other template, and the client's `factory.yml` is just the last layer on top of the template it names. One set of merge rules applies at every layer. We considered keeping templates standalone, with a separate override syntax for `factory.yml`. That would mean two models to specify and document, and an org that wanted to change three tasks in `default` would have to copy the whole template. With layers, customizing the factory and writing a small template are the same act. Templates can come from this repo, from a folder in the client repo, or from another repo pinned by ref. Hooks in a template run with the client's token, so a template from another repo is trusted like any action a workflow `uses:`.
