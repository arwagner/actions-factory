# 2. One generic caller stub, not workflows compiled from config

A client repo copies one fixed caller workflow, `.github/workflows/factory.yml`. It wakes on factory labels (prefix `agent:`), comments, dispatches and a regular schedule tick, and hands every event to a shared router workflow in this repo. The router reads `factory.yml` and the chosen template and decides which task, if any, runs. The other option, compiling exact workflow files from the config (as GitHub Agentic Workflows does), gives exact triggers and no wasted runs, but every change to the config or template would need regenerating and committing workflow files, and those files can drift. We chose the generic stub: onboarding is one file, and switching templates needs no workflow changes. The cost is that the stub wakes for events that come to nothing; a job-level label filter keeps most of those from starting a runner, and the schedule tick is the remaining cost on quiet private repos.
